# ADR-0026 — Authorable local decorative effects

Status: accepted implementation direction for the owner-authorized interactive
Aurora assignment; implementation and acceptance remain pending.

Requirements: bounded SF-0508-001/002/003/004/005/006/007/008,
SF-1101-001/002/003/004/005/006/007/008,
SF-1103-001/002/003/004/005/006/007/008 and
SF-1201-003/004, SF-1204-003/004, SF-1206-003/004.

## Decision

Extend ordinary canonical authoring with optional, versioned typed decorative
configuration. Absence preserves existing documents and output. Validation owns
finite ranges, supported targets and dependencies; inspector drafts do not
become persisted runtime state. A configuration edit uses the normal validated
command/history path and the shared owned appearance-preview lifecycle.

A flowing gradient is bounded local displacement of the gradient's sample
coordinates by pointer movement, followed by time-based return to rest. It is
not a pointer-following colored disk. Radius, strength, response and return time
have separate units and bounded work. Pointer samples, velocities and frames
remain transient. Ordinary native editing renders the resting canonical fill;
explicit website preview runs the generated effect.

The immutable static build plan provides a single SiteForge-owned local runtime
and validated configuration for both Safari preview and exported output.
Configuration is data, never interpolated executable source. Existing URL
escaping, resource ownership and compiler validation remain in force. The
runtime has no network dependency, raw script editor or sample-only branch.
Decorative layers cannot intercept content input. Unsupported features,
JavaScript disabled, reduced motion and no-hover input retain the authored
static design. Animation coalesces input, bounds raster work and retires when
settled, hidden, offscreen or disposed.

Glass appearance similarly remains typed authorable data with an opaque fallback.
Native application appearance is separate from website appearance. Theme-aware
website color choices must remain project data and use the same output model;
they cannot be inferred from the native app's gray chrome.

Footer groups remain ordinary containers and content nodes under the existing
single footer anchor (ADR-0020). Compound insertion/duplication is transactional;
there is no new component/master ownership. QR generation uses a local platform
encoder and the existing content-addressed image pipeline. Its validated payload
and accessible text/link are editable data, with no remote encoder or redirect.
The redesigned example loads through ADR-0023's package/resource validation and
fresh-document creation path, preserving the original sample and owner projects.

## Alternatives and limits

Replacing canonical native layout with browser layout would violate ADR-0013/14.
A sample-only script or bitmap would not provide authoring. A general fluid
simulation framework would add unrelated state, dependencies and cost. None is
required for this bounded local deformation. Unsupported combinations must stay
visible and actionable rather than silently changing fills or claiming parity.

Focused model, history, native input, browser lifecycle and measured performance
receipts are required before delivery. This decision is not a passing test or an
assertion that any whole requirement module has been completed.
