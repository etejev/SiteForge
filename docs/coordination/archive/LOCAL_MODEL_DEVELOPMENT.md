## 1. SF-LOCAL-OUTPUT-ACCESSIBILITY

**Outcome.** An author can use Check Website or Website Preview to find a connected page's missing image alternative text, skipped heading levels, and duplicate main landmarks. The author can open the real object, edit it with existing Inspector controls, and rerun the check. Builds still produce the same valid site files when these findings are present. Scope is the connected static pages covered by the current compiler. The legacy flat output adapter is a later slice.

**Requirements.** `SF-1203-003/004/006`, `SF-1211-003/004/006/008`, `SF-1605-004/006/008`, and Appendix C's generated-site checklist. Read the full clauses. This packet covers three deterministic authoring checks.

**Outcome.** A supported ordinary leaf in a connected body Section can use authored Relative Position offsets and export with the same position and size as the native canvas/Preview at the same width. Read ADR-0020 and the connected structure clarification, plus `docs/evidence/SF-AUTHORING-109-POSITIONING-REUSABLE-STATES.md`, `docs/evidence/SF-AUTHORING-122-CONNECTED-OUTPUT-INTEGRATION.md` and `docs/evidence/SF-LOCAL-BUILDER-011-CONNECTED-FLUID-OUTPUT.md`.

### Code this in order

1. Reproduce the current typed `page-flow-positioning` failure in `Tests/SiteForgeTests/InsertionModelTests.swift`. Reuse `connectedPageSession`, `insertConnectedChild`, and existing fixture property helpers as appropriate. Set `.relative` on one ordinary leaf child of a connected body Section. 2. Establish one shared support predicate for this specific export subset. Start with a single-root connected page using the existing non-fluid, non-automatic layout path. The eligible object is a visible, geometry-bearing ordinary child in a connected `.body` Section that the current adapter renders using absolute child coordinates. Limit to leaf Frame, Text, Image, Button, or Link kinds with a verified authoring-node identity and complete positive fixed dimensions where visible. Exclude page roots, managed chrome and navigation, component-expanded or component-owned objects, Forms, ancestors with non-static positioning, and children the existing output places in relative flow, flex, or a dynamic wrapper. 3. Use the existing relative offset formula from the native position resolver. For this mode the horizontal shift is `left-or-zero minus right-or-zero` and the vertical shift is `top-or-zero minus bottom-or-zero`. If needed, extract just the pure typed offset into the existing positioning or layout model and call it from both adapters. Preserve all other native positioning modes and history. In the supported connected CSS path, apply the shift once to the final existing `left` and `top` expressions after container and breakpoint geometry are resolved. Keep the existing absolute output box mode, dimensions, parent, and z-order. Preserve the continuous containing-width expression with a typed numeric addition where the base offsets are expressed as CSS math. Use the existing safe numeric serializer. Have exactly one owner for the position and inset rules for eligible nodes so raw `right` or `bottom` declarations from `StaticAdvancedStyleOutputEmitter` cannot shift or stretch the result again. Preserve the same node selectors, independent appearance rules, and the legacy path. A zero canonical shift keeps the same geometry.
4. Make the preflight admit only the cases the connected emitter can represent. `StaticBuildCompiler.compile` and direct `MultiPageStaticBuildPlanner.plan` must agree. Clear `page-flow-positioning` only for the admitted case. Keep a redacted repair for unsupported cases under that same code. Use the existing website Preview/export compile entry point and atomic writer. Never bake a sampled plan at 390/768/1440 into authoring properties or add a browser-only document correction. Compile and export must leave revision, identities, authoring history, or saved bytes unchanged.
5. Prove live geometry. Extend a suitable existing connected layout/browser parity test or use the current WebKit fixture/oracle pattern to measure real DOM rectangles at Desktop, Tablet, Mobile and at least one fractional width. Capture actual width, parent rectangle, leaf rectangle, and an unaffected sibling, comparing against immutable native geometry at the same width. Use existing pixel tolerances or one CSS pixel for this fixture if stricter checks are absent. Exercise a signed two-axis offset using both sides, and exact-size behavior with one responsive authored width or height. Preserve current native Preview and connected menu checks. Tests must assert positions and dimensions, not only that CSS text contains a rule.
