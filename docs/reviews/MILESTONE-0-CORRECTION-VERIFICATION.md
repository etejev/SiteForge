## SF-CORRECTION-001 proof summary

The correction introduces one typed transition intent and one asynchronous authorization path for every production replacement. Cancel and failed Save compare a full lifecycle snapshot containing canonical document, persisted history snapshot, project identity, URL, durable fingerprint, phase, display name, failure, and recovery candidate. The UI alert is attached above launch/workspace switching so it remains available during New and Open. Save destination selection is injected for deterministic cancellation and failure coverage; the production default remains native `NSSavePanel`.

Recovery packages now live below the app-owned Application Support recovery directory and use stable project identity in the filename. Automated evidence creates only isolated repository-local injected recovery directories; `./sf test` and `./sf verify` clean their exact fixture root even when testing exits unsuccessfully. Relaunch discovery validates candidates off the main actor before presenting Restore or Discard, and successful durable save removes the corresponding app-owned candidate.

## SF-CORRECTION-002 proof summary

Package and recovery I/O now cross one descriptor-based boundary recorded by ADR-0007. A read opens the parent with macOS no-follow-all-components behavior, opens the final regular file relative to that directory without following links, enforces the existing 8-MiB limit before allocating, reads in 64-KiB chunks, and requires matching device, inode, size, modification time, and change time before and after the read. The returned immutable snapshot contains the exact bytes, SHA-256 digest, byte count, identity, owner/group/mode/link count, extended ACL, and approved extended attributes used by package parsing and lifecycle fingerprint state.

Writes create an exclusive `0600` staging file in the opened destination directory, synchronize content and metadata, revalidate destination and ancestor identity, and use exclusive rename for creation or an identity-checked atomic swap for replacement. The displaced expected object is revalidated after the swap; mismatch triggers rollback without consuming external bytes. Durable replacement accepts only current-user, single-link files and preserves owner, group, mode, extended ACL, and the approved xattr allowlist. Recovery directories require current-user ownership and no group/world access; recovery files additionally require restrictive permissions, matching project identity, and exact candidate fingerprint for deletion.

Eleven new tests use actor barriers rather than timing sleeps. They deterministically exercise source replacement, destination replacement, delete/recreate with identical bytes, source/destination/ancestor symlink swaps, same-inode writes before commit and after atomic swap, rollback of a changed displaced object, sparse oversized input, hard-link and foreign-owner policy, real ACL/xattr/mode preservation, recovery collisions, permission-denied deletion and retry, and exact lifecycle/disk preservation. The retained interrupted-write tests cover precommit interruption. Full verification passes with 104 unit tests and 14 UI tests.

## SF-CORRECTION-003 proof summary

ADR-0008 adds a lifecycle-wide epoch above ADR-0007's identity-bound filesystem commit. Each read, durable Save, Save As, autosave, recovery write or deletion, and document transition has an immutable typed identity containing operation ID, epoch, document ID, project ID, revision, sanitized destination identity, and operation intent. New, Open, Revert, Restore, Close, and successful document adoption advance the epoch and invalidate, cancel, or drain old read/save/autosave/recovery work. Success, failure, and cancellation paths compare the complete identity before touching canonical state, URL, project metadata, fingerprint, history, recovery candidate, failure presentation, or lifecycle phase.

Manual Save first cancels and drains pending or executing autosave, then serializes with another explicit save and captures one immutable revision/history/package. Autosave cannot supersede the durable binding or create a false Save conflict. An edit during Save is intentionally not discarded: the captured revision becomes durable, while the active newer revision stays modified and is written as a recovery candidate. Diagnostics include sanitized operation identity and intent without content or complete paths.

Eleven new tests use injected debouncers and actor barriers without race sleeps. They cross Save and executing autosave with every document transition, cover pending/executing autosave immediately followed by Save, Save As, edit-during-Save, stale successful and failed completion, and cancellation both before preparation and immediately before filesystem commit. Exact assertions cover canonical document, project identity, URL, fingerprint, persisted history, recovery candidate, lifecycle phase, external/durable bytes, write counts, and revision ordering. Full verification passes with 115 unit tests and 14 UI tests.

## SF-CORRECTION-004 proof summary

ADR-0009 separates strict current decoding from compatibility migration. Schema v2 requires creation kind, explicit template identity (including JSON null), pages, and every route/role/provenance/root/node page field; canonical validation rejects empty and rootless current pages. Schema v1 alone decodes through a private compatibility DTO and deterministically migrates empty documents or rootless pages before the result crosses the validated package-adoption boundary. Missing or invalid historical fields are corrupt input, and missing persisted history remains a clean isolated compatibility baseline.

Two tracked, encoder-independent package-v1/schema-v1 fixtures cover an empty document and a rootless legacy page. Their decoded-package SHA-256 checksums and fixed source metadata live beside the Base64 bytes. Tests prove exact stable project, document, page, and root identities; approved routes/roles/provenance; deterministic repeated decode and schema-v2 save/reopen; invalid-variant rejection; and clean history isolation.

Canonical validation reserves `UInt64.max`, while the command session refuses a transaction at `UInt64.max - 1` and also uses checked increment arithmetic. Maximum and near-maximum tests prove no trap, one allowed final commit, typed failure afterward, exact document preservation, and unchanged undo/redo stacks. Full verification passes with 119 unit tests and 14 UI tests.
