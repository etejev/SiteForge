# SiteForge Project Status

Last updated: 2026-07-30.

Milestone 0 feature work and audit corrections are complete. The bounded authoring runway is accepted; `SF-AUTHORING-001` through `SF-AUTHORING-008` now supply the production viewport, deterministic layout, native renderer, undo-neutral selection, transactional frame/plain-text insertion, move/resize transforms, snapping/guides, and inline plain-text editing foundations for Milestone 1.

- Bounded verified foundation slices: native app/test targets, native shell, canonical command model, deterministic project packages, open/save/autosave/recovery, persisted bounded history, approved blank-project defaults, and native launch/loading behavior. This is not an aggregate Milestone 0 release-verification claim.
- Current blank baseline: Home `/`, then Not Found `/404`; one minimum root per page; no sample content; one clean non-undoable creation baseline.
- Compatibility: canonical schema v3 writes deterministic authored-guide state, migrates strict schema-v2 documents to an empty guide collection, and continues to read supported schema-v1 packages with deterministic minimum-page/root migration where required.
- Launch/loading: deterministic real-operation stages cover welcome, blank creation, package read, canonical/history validation, atomic adoption, recovery detection, cancellation, failure, retry, and recovery selection while preserving the last valid project.
- Appearance: navigator, inspector, unified toolbar/title bar, viewport, status, recovery, and launch surfaces use centralized native materials with opaque Reduce Transparency fallback, stronger increased-contrast boundaries, dynamic light/dark appearance, inactive-window treatment, and pass-through hit testing.
- Audit correction: `SF-CORRECTION-001` through `008` close the data-loss, recovery, filesystem-identity, lifecycle-race, schema/migration, macOS file-access, traceability, headless dependency, per-window ownership, accessibility evidence, stable navigator identity, secret scanning, resource-capacity, Open-panel ownership, and fixture-hygiene findings.
- Resource capacity: resource-index v1 keeps package control data at the unchanged 8-MiB/4-MiB/256-member limits while a deterministic content-addressed sidecar supports up to 2,000 resources, 16 MiB each, and 2 GiB total with streamed validation. Native move/copy integration remains downstream authoring work and is not claimed here.
- File access: panel-selected projects receive app-scoped bookmarks in restrictive app-owned storage; subsequent open/revert/save resolves and repairs access, balances security-scope lifetime, coordinates actual package I/O, and detects external change/move/delete without replacing canonical content. The unsigned Release candidate declares App Sandbox and user-selected read/write; Debug/XCTest remains credential-free.
- Authoring runway: isolated native prototypes and a deterministic layout subset retain 25 raw measurement series at 100/10,000 objects, exact browser-geometry parity on the supported subset, a real 500-asset storage exercise, environment/memory/limitations, and five focused behavioral tests. ADR-0013 selects a SiteForge-owned layout engine with an isolated standards oracle; ADR-0014 selects SwiftUI chrome plus an AppKit viewport and bounded Core Animation composition, with Metal optional.
- Canvas viewport: Foundation-only typed world/viewport/device geometry drives a scene-owned AppKit viewport with 25–800% cursor-anchored zoom, bounded pan, deterministic fit/resize, Retina-aware conversion, keyboard and accessibility commands, and revision/generation-scoped actor preparation. Viewport convenience state does not enter canonical project persistence.
- Deterministic layout: the Foundation-only production engine validates one bounded stable-ID graph and computes immutable revision/generation/viewport-tagged frames and provenance for fixed/intrinsic/fill sizing, min/max constraints, padding, gap, alignment, horizontal/vertical stacks, nesting, visible/clip overflow, and responsive widths. Percentage/automatic sizing, baseline alignment, scrolling overflow, unbounded or cyclic graphs, and browser fallback are typed unsupported states rather than approximations. WebKit remains isolated to the evidence/export-oracle adapter.
- Layout evidence: optimized named-host measurements retain raw samples and memory. Production P95 was 0.232 ms at 100 nodes and 22.290 ms at 10,000 nodes; browser geometry matched exactly at 320/768/1,440 points and across the complete 100-/10,000-node fixtures. The large result exceeds one 60 Hz interval and is off-main capacity evidence, not an incremental-layout, renderer, or release-budget pass.
- Native renderer: the AppKit viewport consumes exact identity-tagged immutable scenes and adopts bounded Core Animation content tiles separately from editor overlays. The headless contract defines paint/clipping/visibility, reverse-order hit testing, dirty regions, compositor-only pan/zoom, stable virtual accessibility, deterministic cache eviction, preview overlay exclusion, cancellation/stale gates, and redacted diagnostics. Metal remains absent.
- Renderer evidence: named-host raw samples retain timing and memory for full, one-object dirty, and hit-test paths at 100/10,000 objects plus an idle display-link probe. Full planning P95 was 1.084/75.980 ms; dirty planning was 1.172/113.634 ms; hit testing was 0.001/0.107 ms. All large planning samples exceeded 16.67 ms, so incremental indexing and release performance remain explicitly unproven.
- Selection: each scene/window owns one stable-ID ordered selection with primary/anchor identity and typed provenance. Pointer, keyboard, menu, contextual, Layers, and accessibility adapters share one registry; invalid/stale/cancelled work is state-neutral. Valid identity survives lifecycle/render boundaries while removed, hidden, clipped, unavailable, cross-page, or cross-document targets repair deterministically. Locked objects remain inspectable and non-transformable.
- Selection isolation: selection is noncanonical and undo-neutral, never enters packages, autosave/recovery, persisted history, preview, or export-facing snapshots. Primary/secondary outlines live only in the editor-overlay tree; selection-only updates invalidate bounded old/new regions without layout recomputation or authored-scene rerasterization.
- Selection evidence: retained Mac16,13 optimized measurements record command P95 of 0.073/3.803 ms and overlay-planning P95 of 0.014/0.958 ms at 100/10,000 objects, with 61,177,856-byte process high-water memory, raw samples, methodology, and limitations. Running-app dark-appearance screenshots retain empty, single, and multiple states. This does not prove final incremental indexing, interactive Instruments/frame pacing, OS-level VoiceOver/settings coverage, or OD-001 budgets.
- Frame/text insertion: a Foundation-only typed registry compiles validated frame and plain-text requests into one canonical transaction and exact stable-ID inverse. Scene-owned inactive/armed/previewing/committing/cancelled/failed insertion state never enters serialization or history; successful commits alone update selection, Layers, layout, renderer, hit testing, preview/package snapshots, autosave/recovery, and persisted undo/redo. Frame defaults are 240×160; bounded plain text defaults to `Text` at 120×24, all recorded as `.defaulted` rather than explicitly authored values.
- Insertion compatibility and limits: schema v2 remains unchanged and deterministic; supported schema-v1 packages still pass through the strict existing migration adapter. Validation rejects stale identity/revision/generation, invalid or cross-page parents, locked/hidden/unavailable destinations, invalid order/geometry, duplicate IDs, cycles, depth over 256, documents over 20,000 nodes, and text over 64 KiB without mutation. The canonical graph validator is now iterative and set-backed rather than recursive/quadratic.
- Insertion evidence: retained Mac16,13 optimized measurements record insertion-command P95 of 0.756/44.961 ms, layout P95 of 0.897/68.002 ms, and renderer preparation P95 of 1.289/93.654 ms at 100/10,000 objects, with 159,596,544-byte resident-memory high water, raw samples, environment, methodology, and limitations. The large layout/render results exceed one 60 Hz interval; production shaping, incremental layout/render indexes, interactive frame pacing, cross-hardware budgets, and release acceptance remain unproven.
- Geometry transforms: one Foundation-only typed registry and scene/window-owned noncanonical session implement deterministic draft → validate → preview → commit move and eight-handle resize operations against the existing canonical `layout.x/y/width/height` properties. Exact document/page/revision/scene/generation/session identities, finite geometry, selection order, availability, ownership, and lifecycle state gate every operation. Compatible multiple selection can move atomically; multiple resize and any incompatible subset are rejected explicitly rather than coerced.
- Transform integration: genuine pointer drags use bounded native accessible handle views, while keyboard, menu, contextual, inspector numeric, accessibility, and automation paths share the registry. Previews and handles remain in the editor-overlay tree and outside packages/history/preview/export snapshots; successful completion alone creates one transaction/inverse and then updates selection, Layers, layout, renderer, hit testing, old/new dirty regions, persistence, autosave/recovery, and persisted history. Escape/cancellation and stale/failed work preserve canonical and selection state.
- Transform evidence: thirteen focused unit/integration tests and one running-app journey retain pointer resize/move, keyboard/numeric, undo/redo, Escape, Layers, focus, and accessibility evidence. Mac16,13 optimized transform preparation P95 was 0.629 ms in a 100-object project and 28.493 ms in a 10,000-object project, with 110,804,992-byte resident-memory high water. The large result exceeds one 60 Hz interval and does not prove final incremental layout/render performance, 10,000-object simultaneous selection, cross-hardware budgets, or release acceptance.
- Snapping and guides: the existing transform draft is resolved through a Foundation-only deterministic candidate engine before the same transform registry revalidates preview and commit. Entry/exit tolerances are 6/9 logical screen points; authored guides outrank object edges, edges outrank centers, X/Y resolve independently, stable identity breaks equal-distance ties, and the prior winner remains through the exit envelope. Hidden, clipped, unavailable, selected, and cross-page objects are excluded while locked objects remain immutable references; Option and an accessible command suppress snapping.
- Guide integration: only explicitly authored page-owned horizontal/vertical guides enter canonical schema v3. Stable `GuideID`, finite bounded positions, provenance, and deterministic array order persist through packages and history; add/move/remove use the central typed command registry, one transaction/inverse, and exact undo/redo. Candidates, winners, measurements, ruler interaction, smart-guide overlays, and transform previews remain editor-only and do not create a second geometry source.
- Snapping evidence: six focused unit/integration tests and one running-app ruler/guide/suppression/accessibility journey cover priority, ties, hysteresis, zoom, cancellation/stale neutrality, eligibility, command provenance, exact history/package round trips, schema-v2 migration, preview/commit parity, redaction, native overlays, and bounded scale. Retained Mac16,13 optimized resolver P95 is 0.972 ms at 100 objects and 40.341 ms at 10,000 objects, with 109,428,736-byte resident-memory high water, raw samples, environment, methodology, and limitations under `docs/evidence/snapping-guide-foundation/`. The bounded full scan exceeds one 60 Hz interval and is not final incremental or renderer performance evidence.
- Inline plain-text editing: one scene/window-owned noncanonical session validates stable document, page, revision, renderer-generation, session, and text-node identity before committing the existing `content.text` property through exactly one central transaction and inverse. A native `NSTextView` owns the caret, selection, multiline editing, clipboard, and marked-text composition; double-click, keyboard, menu, contextual, accessibility, and automation activation share the same typed registry. Escape, invalid input, stale identity, node removal, and lifecycle replacement preserve the last committed text.
- Text-editing integration and evidence: committed text adopts through selection, Layers, layout, renderer, hit testing, bounded dirty regions, deterministic packages/history, autosave/recovery, undo/redo, focus, and accessibility announcements, while draft text, ranges, composition, clipboard state, and editor overlays never enter canonical serialization, history, preview, or export-facing snapshots. Thirteen focused unit/integration tests plus one actual-app editing journey cover native pointer/keyboard activation, replacement/newline, copy/cut/paste, commit/cancel, undo/redo, accessibility, and renderer adoption. Retained Mac16,13 Debug-test measurements record command-preparation P95 of 0.819 ms at 100 objects and 2.419 ms at 10,000 objects, with 108,314,624-byte resident-memory high water; native input, layout/raster, I/O, incremental indexing, OS-level IME/VoiceOver, production typography, and release budgets remain unproven.
